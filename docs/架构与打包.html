架构与打包说明

本文面向二次开发/维护者：说明各层职责、数据流、协议实现要点，以及安装包是怎么拼出来的。

1. 分层设计

┌──────────────────────────────────────────────────────────┐
│ gui/          即时模式 UI（pygame 自绘，无 tkinter 依赖） │
│   app.py 主循环 · widgets.py 控件 · screens/* 四个页面     │
├──────────────────────────────────────────────────────────┤
│ core/         设备与输入抽象                              │
│   device_manager ─┬─ backend_sdl (pygame/SDL2)            │
│                   └─ backend_hid (hidapi + joycon 协议)    │
│   mapping（JSON 方案 / 捕获 / 输出换算）                   │
│   rumble（波形引擎） · virtual_pad（ViGEmBus 输出）        │
├──────────────────────────────────────────────────────────┤
│ platform/     Windows 原生能力                            │
│   win_keyboard（SendInput） · win_dialog（comdlg32）       │
└──────────────────────────────────────────────────────────┘

上层只依赖 DeviceInfo / PadState 两个数据结构，新增后端（例如 raw HID、XInput 直连） 不需要改界面：实现 enumerate() / poll() / rumble() 后在 DeviceManager 里注册即可。

数据流

  1. App._update() 每帧（60Hz）调用 DeviceManager.poll(device)；
  2. SDL 后端把 b0..bN / a0..aN / hat 换算成语义按键与轴（layouts.sdl_state）；

HID 后端从读取线程取最新解析结果（joycon.parse_report）；

  1. MappingProfile.evaluate(state) 用死区/反转后的轴值与阈值，算出本帧要输出的动作集合；
  2. 输出分发到 KeyboardInjector（SendInput）或 VirtualPad（vgamepad）；
  3. 界面只读状态，不写设备，保证「测试」与「输出」解耦。

2. 输入后端

SDL 后端

Windows 下 SDL 对所有手柄统一了「Game Controller」通道顺序：

按钮 0..14 = A B X Y BACK GUIDE START LS RS LB RB UP DOWN LEFT RIGHT
轴   0..5  = LX LY RX RY LT RT（扳机为 -1..1，程序归一化到 0..1）

十字键既可能出现在按钮位，也可能是 hat，layouts.sdl_state 两者都处理。 震动走 Joystick.rumble(low, high, ms)（SDL 在 Windows 上转成 XInput 触觉指令）。

HID 后端（Nintendo）

Joy-Con 单只使用时 SDL 只能看到半个手柄，且蓝牙下很难输出震动，因此对 Nintendo 设备 （VID 0x057E）改用 hidapi 直连：

* 打开设备 → 请求 standard full 输入报文（子命令 0x03 / 0x30）→ 读取线程循环 read(64)； * 兼容 0x21（simple HID）与 0x30（full）两种报文，前置布局相同： [2] 电量/连接、[3][4][5] 三组按键、[6..8] 左摇杆、[9..11] 右摇杆； * 摇杆是 12 位（低 8 位 + 高 4 位打包），中心 2048，Y 轴硬件向下为正，解析时翻转； * 震动用 0x10 报文持续下发（约每 20ms 一次），振幅/频率按官方公式编码：

encoded_freq = round(log2(freq/10) * 32)
hf = (encoded_freq - 0x60) * 4      # 0x0004..0x01FC，步进 4
lf = encoded_freq - 0x40            # 0x01..0x7F

amp > 0.23 → encoded_amp = round(log2(amp*8.7) * 32)
amp > 0.12 → encoded_amp = round(log2(amp*17)  * 16)

byte0 = hf & 0xFF
byte1 = (encoded_amp << 1 & 0xFF) + (hf >> 8)
byte2 = lf + (((encoded_amp >> 1) + 0x40) >> 8)
byte3 = ((encoded_amp >> 1) + 0x40) & 0xFF

静默包固定为 00 01 40 40，程序里作为 NEUTRAL_RUMBLE 常量。

3. 映射引擎

* 来源（source）统一语法：button:<语义键>、axis:<轴>:<+ / ->； * active_sources() 把一帧输入转成「被触发的来源 → 强度」； * evaluate() 只输出超过阈值的轴绑定（默认 0.55），按钮绑定直接为 1.0； * 死区用径向死区（radial_deadzone），避免斜向推动时出现方形死区； * 方案文件带 schema 字段，版本不匹配时拒绝加载，加载时对未知来源/未知按键做清理并记录警告。

4. 界面

pygame 自绘 + 即时模式控件（UI.begin() → 各控件函数返回交互结果 → draw_overlays()）：

* 好处是不依赖 tkinter（Windows 的 embeddable Python 不带 Tcl/Tk）， 整个程序只需要 pygame 一个 GUI 依赖，且 60Hz 重绘摇杆/扳机毫无压力； * 中文字体随包分发的 NotoSansSC.otf，避免不同机器字体缺失导致豆腐块； * --screenshot <dir> 可以在无显示器环境（SDL dummy driver）下把四个页面各渲一张 PNG， 便于改版时回归对比，--demo 会注入一份虚拟输入数据，用来检查高亮/数值渲染路径。

5. 打包

python build/build_installer.py     # 一步出安装包（下载 runtime、装 wheel、调 makensis）

build_installer.py 做的事：

  1. 下载 python-3.11.9-embed-amd64.zip（Windows 版可嵌入运行时，约 11MB），解包到 build/payload/runtime；
  2. 改写 python311._pth，把 Lib\site-packages 加进搜索路径并启用 site；
  3. 用 pip install --target ... --platform win_amd64 --python-version 311 --abi cp311 --only-binary=:all:

把 pygame / hidapi / inputs 的 Windows wheel 直接铺进去（在 Linux 上也能出 Windows 包）；

  1. vgamepad 没有 wheel，取 sdist 解包（纯 Python + 自带 ViGEmClient.dll）；
  2. 拷贝程序源码、字体、示例方案、文档、tools/bootstrap.py、ViGEmBus 安装包；
  3. 调 makensis 生成 dist/GamepadStudio-Setup-1.0.0.exe。

安装包体积来自四块：runtime 约 50MB（含 pygame）、字体 16MB、ViGEmBus 6MB、程序本体 1MB。

依赖部署策略

阶段行为
打包时依赖库已冻结进安装包（离线可装，无需联网）
安装时python.exe tools/bootstrap.py --quiet 做导入自检，结果写 runtime/bootstrap.log
缺失时bootstrap 从 PyPI 取对应 cp311-win_amd64 wheel，按 zip 解包到 site-packages（不需要 pip）
驱动检测 HKLM\SYSTEM\CurrentControlSet\Services\ViGEmBus，缺失则静默安装 ViGEmBus

6. 测试

PYTHONPATH=src python -m unittest discover -s tests -t .

* tests/test_joycon.py：报文解析（面键/系统键/摇杆/电量/单只 Joy-Con）、震动编码范围与报文布局； * tests/test_mapping.py：死区、反转、阈值、来源捕获、JSON 往返、非法方案清理； * 界面回归：python -m gamepadstudio.main --screenshot build/shots --demo。

7. 已知限制

* SDL 的震动接口在部分第三方手柄上只是「声明支持但无实际效果」，程序会在「关于」页标出通道状态； * Joy-Con 的 IMU（陀螺仪/加速度）报文已读取但未在界面展示，可在此基础上扩展体感测试； * 虚拟手柄目前支持 Xbox 360 / DualShock 4 两种目标，未做 DualSense 的扳机自适应阻力； * 键盘注入仅 Windows；其他系统可运行测试台，但输出目标会被禁用。
